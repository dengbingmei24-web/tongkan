# 同看（Tongkan）产品与架构决策日志

> 作用：记录跨对话仍然有效的决定，防止 AI 在后续开发中重复讨论、误改方向或恢复已放弃方案。
> 规则：已接受的决策不得静默删除；被替代时标记“已取代”，并指向新决策。

## 使用方法

开始涉及产品、架构、协议、UI 或版本规划的任务前，搜索相关关键词：

```powershell
Select-String -Path docs/decisions/DECISIONS.md -Pattern "片单|主题|全屏|协议"
```

新增决策使用以下格式：

```text
## D-XXX 决策标题
- 日期：YYYY-MM-DD
- 状态：提议 / 已接受 / 已取代 / 已放弃
- 范围：产品 / Android / Web / 信令 / 协议 / 设计 / 发布
- 决策：一句话说明最终选择
- 原因：为什么这样选择
- 影响：哪些代码、文档或测试受影响
- 替代方案：讨论过但没有采用的方案
```

## D-001 房间固定最多两人

- 日期：2026-08-03
- 状态：已接受
- 范围：产品、信令
- 决策：每个房间固定为房主和访客两个成员槽位，不扩展多人群组。
- 原因：产品是双人自用工具，多人会显著增加同步、权限和界面复杂度。
- 影响：Durable Object 成员模型、房间满员错误、UI 文案和 QA。

## D-002 无注册登录，使用临时密钥

- 日期：2026-08-03
- 状态：已取代（D-059）
- 范围：产品、信令、安全
- 决策：不建立账号系统，通过创建房间得到的临时密钥进行房主和访客认证。
- 原因：降低使用和维护成本，符合个人双人场景。
- 影响：该限制已由 D-059 取代；匿名临时房间仅作为兼容与回退能力，账号、唯一好友和云端双人空间进入 Alpha 10。

## D-003 服务端只同步控制状态

- 日期：2026-08-03
- 状态：已接受
- 范围：架构、信令、协议
- 决策：服务器同步媒体身份、播放锚点和控制消息，不代理、转码或中转 B站视频流。
- 原因：避免带宽、版权、部署和稳定性成本。
- 影响：双方客户端直接加载同一媒体；播放器能力取决于客户端环境。

## D-004 Android 使用原生 Java + WebView

- 日期：2026-08-03
- 状态：已接受
- 范围：Android
- 决策：Android 保持原生 Java、动态 View 和 WebView，不迁移 Kotlin、Compose 或跨平台框架。
- 原因：项目规模小、现有代码可维护，不需要重写成本。
- 影响：UI 和状态管理集中在 `MainActivity.java`；新增能力优先使用平台 API。

## D-005 Alpha 7 是 Android 稳定回退基线

- 日期：2026-08-07
- 状态：已接受
- 范围：Android、发布
- 决策：`1.0.0-alpha.7`、`versionCode 7` 是当前开发和安装基线。
- 原因：Alpha 7 完成 OkHttp WebSocket 迁移并通过干净测试与 Debug APK 构建。
- 影响：后续实验必须能回退到 Alpha 7；不得把 Alpha 8 误认为当前版本。

## D-006 Alpha 8 移动 B站页面实验归档

- 日期：2026-08-07
- 状态：已接受
- 范围：Android、播放器
- 决策：直接加载 B站移动视频页的 Alpha 8 实验不继续作为主线方案。
- 原因：没有足够真实设备证据证明其优于 Alpha 7，且不能用实验覆盖稳定基线。
- 影响：APK 保留用于比较；重新启用前必须做隔离实验和实机验证。

## D-007 Android 采用分阶段页面流程

- 日期：2026-08-07
- 状态：已接受
- 范围：产品、Android UI
- 决策：App 启动先显示房间入口；创建或加入后进入视频准备；加载完成后进入观看。
- 原因：旧界面启动即展示播放器、输入和控制，信息顺序差且像调试页面。
- 影响：Alpha 9 需要显式界面状态，未进入房间前隐藏视频控制。

## D-008 全屏不自动横屏

- 日期：2026-08-07
- 状态：已接受
- 范围：Android UI
- 决策：点击全屏保持当前方向，只有用户点击“横屏”才切换方向；返回键优先退出全屏并恢复原方向。
- 原因：避免强制旋转打断使用，同时满足横屏观看需求。
- 影响：需要 WebChromeClient 自定义视图、方向状态保存和 Back 恢复。

## D-009 Alpha 9 视觉方向为 C·简洁工具感

- 日期：2026-08-07
- 状态：已接受
- 范围：设计、Android UI
- 决策：选择清晰、克制、轻量的工具型视觉，不使用霓虹、复杂渐变或恋爱软件风格。
- 原因：用户不喜欢旧界面和其他候选方向，希望直接、耐看、低学习成本。
- 影响：以 `design/alpha9-ui/SELECTED_DESIGN.md` 为视觉真源。

## D-010 默认浅色，可选黑灰深色

- 日期：2026-08-07
- 状态：已接受
- 范围：设计、Android UI
- 决策：默认浅色；用户可以切换深色并持久化。深色使用黑色和中性炭灰，绿色只用于在线和成功状态。
- 原因：用户明确拒绝绿色调深色主题，要求深色是黑色。
- 影响：主题保存到本地；切换主题不得重连房间或重载视频。

## D-011 控件圆角系统

- 日期：2026-08-07
- 状态：已接受
- 范围：设计
- 决策：主要/次要按钮、输入框和图标按钮使用 12dp；普通卡片使用 16dp；胶囊仅用于短状态标签。
- 原因：减少过度圆润，提高简洁工具感。
- 影响：所有 Alpha 9 原生组件和设计审计。

## D-012 主题切换位于各页面右上角

- 日期：2026-08-07
- 状态：已接受
- 范围：Android UI
- 决策：房间入口、视频准备和观看页面右上角都提供太阳/月亮主题按钮。
- 原因：直接可发现，不把简单能力藏进设置菜单。
- 影响：48×48dp 触控区、12dp 圆角、无页面重建式切换。

## D-013 按钮使用三阶段交互反馈

- 日期：2026-08-07
- 状态：已接受
- 范围：Android UI、交互
- 决策：按钮必须提供按下变色/波纹、执行中的图标与文案、成功或失败结果反馈。
- 原因：用户反馈点击后常怀疑没有点到。
- 影响：使用 `RippleDrawable`、状态色、禁用重复点击和就近错误提示，不新增依赖。

## D-014 视频准备成功后自动进入观看页

- 日期：2026-08-07
- 状态：已接受
- 范围：产品、Android UI
- 决策：视频准备成功后不显示二次确认按钮，自动进入观看页面。
- 原因：减少无意义操作；失败时仍停留在准备页。
- 影响：加载状态必须清楚，不能进入空播放器页面。

## D-015 第一版片单是 Android 本地长期片单

- 日期：2026-08-07
- 状态：已接受
- 范围：产品、Android、存储
- 决策：第一版片单长期保存在本机，跨房间和重启保留；不做双方共享编辑。
- 原因：满足减少重复粘贴链接的需求，同时不扩大房间协议和冲突处理范围。
- 影响：本机保存链接、顺序和元数据缓存；只通过现有 `media-change` 同步当前选择。

## D-016 片单切换后停在 0 秒

- 日期：2026-08-07
- 状态：已接受
- 范围：产品、播放同步
- 决策：新视频加载完成后进入观看页，但停在 0 秒并保持暂停，等待手动播放。
- 原因：避免两端加载速度不同导致错过开头。
- 影响：更换视频遮罩结束后不得自动发送播放命令。

## D-017 第一版不自动连播

- 日期：2026-08-07
- 状态：已接受
- 范围：产品、片单
- 决策：视频结束后显示“播放下一个”和“返回片单”，不自动切换。
- 原因：用户希望按需求选择，不希望意外播放下一个。
- 影响：自动连播只能作为以后默认关闭的选项。

## D-018 片单使用显式排序模式

- 日期：2026-08-07
- 状态：已接受
- 范围：Android UI、片单
- 决策：普通模式隐藏拖动控件；点击“排序”后显示拖动把手，长按拖动并自动保存；菜单保留上移、下移、移到顶部和删除。
- 原因：兼顾普通浏览简洁和排序效率。
- 影响：播放按钮和拖动把手不能同时造成误触；删除当前项不停止当前播放。

## D-019 房间入口页不展示片单

- 日期：2026-08-07
- 状态：已接受
- 范围：Android UI、片单
- 决策：房间入口页保持创建/加入功能；进入房间后在准备视频页展示片单，观看时通过底部弹层打开。
- 原因：避免入口页重新变得复杂。
- 影响：批量添加使用底部面板，支持多行链接、重复识别和后台元数据加载。

## D-020 下一开发版本为 Alpha 9

- 日期：2026-08-07
- 状态：已接受
- 范围：Android、版本规划
- 决策：Alpha 7 保持当前稳定安装和回退基线；Alpha 8 作为已归档实验；下一次开发、构建和测试版本使用 `1.0.0-alpha.9`。
- 原因：`docs/product/ANDROID_FOLLOWUP_PRD.md` 已明确版本路线，用户再次确认下一版本是 Alpha 9，不能把 Alpha 7 基线或 Alpha 8 实验误写为下一版本。
- 影响：开始原生实现前仍需冻结 Alpha 9 最终范围；在 APK 实际构建完成前，不得把 Alpha 9 描述为当前已安装版本。

## D-043 持续缓冲超过 2 秒时双方同步暂停

- 日期：2026-08-07
- 状态：已接受
- 范围：Android 播放器桥接、房间同步、缓冲 UX
- 决策：本地缓冲不超过 2 秒时不影响房间；持续超过 2 秒后只上报一次缓冲并触发双方同步暂停。恢复后不自动播放，任意一方手动播放才继续。
- 原因：忽略短暂抖动可以避免频繁打断，但持续缓冲时让另一方继续播放会导致一方漏看内容并产生明显进度分歧。
- 影响：卡顿方显示“正在缓冲”，对方显示具体昵称和“已一起暂停”；15 秒仍未恢复时提供“重新加载播放器”和“在 B站打开”。当前 Android Bridge 会立即上报 waiting，服务端收到首个 buffering=true 就暂停房间，因此 Alpha 9 必须在 Android 端增加 2 秒防抖并确保每次缓冲过程只上报一次。

- 非目标：Alpha 10.3 不加入自动提醒、重复计划、外部日历、多人/私密计划或实际共同观看历史。月历真实观看实心点、双标记和“实际观看”分组继续属于 Alpha 10.4。
- 原因：独立 revision 避免片库排序或元数据更新与日历编辑互相制造冲突；媒体快照保证条目删除、解绑归档和后续元数据变化时仍能解释原计划；planned/completed 与 planned-only today 查询形成最小闭环，不需要提前引入统计系统。
- 影响：新增 `0007_calendar_plans.sql`、日历 API、Account/D1 测试、Android 日历/首页/片库入口和 16-case QA 合同。当前仅在 `codex/TK-004-calendar` 本地集成；Preview/生产 migration、Worker 部署和 APK 发布仍需分别授权。
