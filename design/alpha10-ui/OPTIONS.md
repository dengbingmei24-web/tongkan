# 同看 Alpha 10 UI 设计演进与 Breath Tech 定稿

> 状态：Breath Tech 已替代 Air/Cinema/Together，成为 Alpha 10 唯一生产设计方向；旧方案保留为历史探索，尚未进入 Android 生产实现。
> 创建日期：2026-08-11
> 范围：账号登录、绑定后首页、共享片库、日历、“我们”页面。

## 共同约束

- 默认浅色，可切换黑灰深色；绿色只表达在线/成功。
- Android 顶部安全区、48dp 触控目标、清晰按下态和系统返回行为必须保留。
- 底部导航固定为：首页 / 片库 / 日历 / 我们；观看页继续独立沉浸，不显示底部导航。
- 邮箱验证码登录，保留“暂时使用匿名房间”。
- 片库完全共享；日历日期必填、时间和备注可选；头像使用内置资源。
- 视觉参考 Apple HIG 的内容优先、清晰层级、克制材质、熟悉导航和充足留白，但不复制 Apple 产品像素或品牌资产。

## 方案 A · Air / 原生空气感（推荐作为基础）

- **结构**：大标题 + 边到边列表 + 少量悬浮材质，最接近现代系统 App。
- **气质**：安静、清楚、轻盈、低学习成本。
- **优点**：账号、片库、日历等工具页面最耐看；原生 Java View 实现风险最低。
- **风险**：如果完全照此执行，双人产品的情感辨识度略弱。
- **建议**：作为全局设计系统基础，引入方案 C 的双人关系元素。

## 方案 B · Cinema / 黑色影院感

- **结构**：内容海报主舞台 + 浮层数据 + 深黑导航，接近媒体消费产品。
- **气质**：沉浸、电影感、视频优先。
- **优点**：从首页进入观看的欲望最强，和横屏播放器自然衔接。
- **风险**：账号设置、日历和大量文字页面长期使用偏重；不适合强制全 App 黑色。
- **建议**：可作为深色主题和观看相关页面的视觉来源，而不是单独承担全部页面。

## 方案 C · Together / 温暖双人感

- **结构**：关系状态作为页面轴心，计划和回忆围绕两个人组织。
- **气质**：亲密、温和、有产品个性，但避免粉色恋爱模板。
- **优点**：最能表达“固定两个人长期一起看”，首页和“我们”页辨识度最高。
- **风险**：如果颜色和装饰继续增加，容易失去工具感。
- **建议**：控制暖色面积，只把关系组件与历史回忆引入方案 A。

## 当前推荐组合

采用 **A 的系统骨架 + C 的双人关系表达 + B 的观看页深色沉浸**：

1. 登录、片库、日历和设置使用 A。
2. 首页好友状态、绑定天数和共同回忆使用 C。
3. 观看页、横屏和视频切换反馈使用 B 的黑色媒体舞台。

## 原型操作

打开 `options.html`：

- 顶部可切换登录、首页、片库、日历、我们。
- 可切换浅色/深色。
- 三台手机会显示同一页面，方便直接比较结构。

## 2026-08-11 组件化重设计

用户确认三套色系都保留，但要求重做按钮和界面组件。新版参考 shadcn/ui 的组件组织方式，并按 Android 原生 Java 可实现范围重新表达，不直接依赖 React 或复制网页组件代码。

### 统一组件规则

- 按钮统一为 46dp 主高度、11dp 圆角，包含主按钮、描边按钮、危险按钮和图标按钮；按下时轻微缩放，异步操作展示禁用、加载和完成反馈。
- 卡片统一使用 14dp 圆角与 1px 轻边框；阴影只用于关系焦点卡或媒体主舞台，普通列表不堆叠悬浮阴影。
- 筛选使用 Tabs 结构，选中项通过实色表面与轻阴影表达，不使用一排高饱和胶囊。
- 表单使用明确标签、帮助文字、焦点描边和适合邮箱的输入类型；不只依赖 placeholder 说明字段用途。
- 底部导航使用固定安全区、顶部分隔线和克制的矩形选中态；观看页仍不显示底部导航。
- 新增、改期、换片等补充任务统一使用底部 Drawer；高频主操作继续直接露出，不藏进右上角菜单。
- 图标统一使用 1.8px 线性 SVG；所有触控目标不小于 44px，Android 实现时按 48dp 执行。

### 三套保留色系

- **Air**：蓝灰中性色，适合账号、工具列表和默认浅色体验。
- **Cinema**：黑白与低饱和暖金，适合媒体内容、深色主题和观看衔接。
- **Together**：暖杏底色与克制紫色强调，适合关系状态、共同计划和回忆。
- 三套色系共享同一组件几何、间距、交互状态和信息架构，不再通过完全不同的圆角与卡片结构制造差异。

### 新版原型文件

- `options.html`：保持原入口，自动转入新版组件化原型并保留页面与主题查询参数。
- `options-shadcn.html`：新版比较画布。
- `options-shadcn.css`：三套色系、浅深模式与组件 Token。
- `options-shadcn.js`：登录、首页、片库、日历、“我们”、按钮状态、Toast 与 Drawer 交互。

新版浏览器 QA：五个页面均无 JavaScript 错误；三台 376×830 可视区域无横向或纵向内容溢出；按钮已验证“正在创建房间 → 房间已创建”，底部 Drawer 已验证打开、确认和保存反馈；深色外层画布为中性黑 `rgb(12, 13, 16)`。

## Air 最终选择与触感深化

- 用户选择 A · Air 作为唯一页面结构，Cinema 和 Together 仅保留为黑金、暖杏配色。
- 原型从三台并排比较改为一台 Air 手机，通过顶部配色开关切换蓝灰、黑金和暖杏。
- 主按钮增加顶部高光、近阴影、柔和主题色远阴影和底部暗边；按下时下沉 2px 并缩短阴影。
- 描边按钮、图标按钮、底栏选中态、输入框和关键卡片建立不同表面高度；普通列表继续保持平面。
- 状态栏图形替换为统一 SVG，删除临时字符图标。
- 手机外框从 iPhone Dynamic Island 改为中性 Android 打孔屏和更薄边框，避免误导 Android 安全区判断。
- 最终 Android Token 和交互映射以 `SELECTED_DESIGN.md` 为真源。


## 2026-08-11 Breath Tech 全面重设计

用户认为 Air 仍有明显古早感，明确要求推翻旧方案并重新设计科技感、呼吸轻盈感的黑白双主题界面。新版不再保留三套配色作为生产主题，而是收束为中性白和中性黑两套长期主题，冷光蓝只承担连接和焦点语义。

- 新原型：`breath-tech.html`、`breath-tech.css`、`breath-tech.js`。
- `options.html` 保持统一预览入口并重定向到 Breath Tech。
- 五个页面重新建立信号轨道、留白、弱边界、边到边列表和单色反转按钮。
- 主按钮取消旧式高光渐变和下沉拟物，改为即时颜色/边界/轻缩放反馈，并保留加载、禁用、成功和 Toast。
- 白色主题使用 `#F7F8FA`，黑色主题使用 `#05070A`；默认白色。
- 390×844 Android 打孔屏原型中，10 种页面/主题组合均无溢出，触控目标至少 44px，交互回归通过。
- 生产规范以 `SELECTED_DESIGN.md` 为准。
